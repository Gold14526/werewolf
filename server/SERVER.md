# 联机服务

运行 `npm start`（Node.js 22 或更新版本；无 npm 依赖），打开 `http://localhost:3000`。同一个服务同时提供页面和游戏 API。同一局所有玩家必须连接同一个服务实例。

## GitHub Pages + 独立后端

GitHub Pages 只能托管静态前端。将此仓库部署到支持 Node.js 或 Docker 的服务器，再将前端的服务地址配置成后端的 HTTPS 地址。后端设置：

```sh
ALLOWED_ORIGINS=https://YOUR_NAME.github.io
PORT=3000
```

`ALLOWED_ORIGINS` 可填多个逗号分隔的精确 origin，不含路径。例如 GitHub Pages 网站 `https://alice.github.io/moonwolf/` 对应 `https://alice.github.io`。同源访问默认允许；跨域来源必须显式配置。浏览器通过 Bearer token 登录，token 不放入 URL。

附带 `render.yaml` 可作为 Render Blueprint 导入的配置起点；示例指定付费 `starter` 实例以减少空闲休眠中断。部署前在平台确认当前套餐和费用，并填入允许的前端来源。不需要 Render 时，可直接运行 Docker：

```sh
docker build -t moonwolf .
docker run --rm -p 3000:3000 -e ALLOWED_ORIGINS=https://YOUR_NAME.github.io moonwolf
```

## 运行边界

这是单实例内存房间服务。进程重启会清空房间、对局和登录状态；不要横向扩容为多个独立实例。等待房间中的玩家超过 2 分钟无请求会被移除；活跃对局保留玩家席位并由计时器继续推进；30 分钟无人访问的房间自动删除。登录状态最长空闲 24 小时。上线大量公开用户前，应增加持久化、统一房间路由和更完善的反滥用措施。

房号由密码学随机数生成，范围为 `100000`–`999999`，生成时检测现有房间冲突。房号是邀请凭据，私人房间不会出现在公开房间列表。匹配固定采用 12 人默认标准配置；匹配者自动准备，12 人到齐自动开始。自定义房间由房主在满员且全员准备后开始。

服务端独立验证身份、角色权限、目标、阶段与投票，只向每位玩家发送其可见身份与私有信息。客户端不能通过修改页面获得其他玩家的隐藏身份。每局游戏进行中不允许主动退出房间；关闭页面后可在当前登录状态下重新连接。

## 历史记录、排行榜与聊天

`GET /api/history` 返回最近 100 场内当前用户可访问的已结束对局；公开房间记录可由所有登录用户阅读，私人房间记录仅对参与者可见。`GET /api/history/:code` 返回复盘快照，对局结束后身份及狼人密聊公开给有权阅读该记录的用户。`GET /api/stats` 返回当前服务运行期间的胜场、局数和百分比胜率；每局只结算一次。以上记录均保存在内存，重启清空，不是跨设备账号系统。

公开聊天仅允许轮到发言或遗言的玩家发送；夜间狼人密聊仅允许当前仍存活的狼人发送，内容在对局结束前不发给好人。等待大厅及对局结束后可自由公开发言。消息最多 500 字，单房间按发送顺序保留最近 2000 条（公开聊天与狼人密聊合计）。`POST /api/session` 携带已有 Bearer token 可恢复身份，等待阶段可修改昵称，对局中不能改名。
